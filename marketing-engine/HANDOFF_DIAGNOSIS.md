### Три ключевые проблемы

#### 1. В мониторинге всего ОДИН чат, и тот не HR

`data/hr_chats.json` содержит ровно одну запись:

```json
{
  "chat_id": -1001158193643,
  "title": "📣Работа и Вакансии",
  "username": "moskva_v_moskve_vakhtoy",
  "type": "supergroup",
  "members_count": 972010,
  "is_channel": false
}
```

Это вахтовая доска объявлений для Москвы. В ней публикуются вакансии («МАСТЕР ПО ХИМЧИСТКЕ МЕБЕЛИ 90-140K»), а не вопросы соискателей. Артёму туда вписывать рекомендации откликера бессмысленно: чат работает как доска, его комменты потеряются среди объявлений работодателей.

**Что нужно:** 10-30 актуальных HR-чатов, где соискатели реально спрашивают про резюме, собеседования, HH-стратегию. Кандидаты для поиска: чаты карьерных консультантов, чаты для джунов/мидлов в нишах (продажи, маркетинг, бухгалтерия, разработка), HR-сообщества где тусуются и соискатели, выпускники онлайн-школ.

#### 2. Единственный чат заблокирован баном (расхождение форматов chat_id)

Сегодня в 06:01 UTC userbot поймал релевантное сообщение в чате `1158193643`, скоринг 0.85, поставил отложенный ответ через 118 секунд. На отправке сработал check `userbot.auto_send_skipped_banned`.

При этом в `data/banned_chats.json` лежит ДРУГОЙ ID:

```json
{"banned": [
  {
    "chat_id": -1001055285015,
    "raw_chat_id": 1055285015,
    "banned_at": "2026-04-23T03:14:18.491393+00:00",
    "reason": "ChatWriteForbiddenError",
    "title": "РАБОТА | ВАКАНСИИ"
  }
]}
```

То есть `1158193643` нет в файле баном, но проверка `if chat_id in self._banned_chat_ids or send_chat_id in self._banned_chat_ids` сработала. Возможно в `_banned_chat_ids` (set в памяти) был добавлен ID после загрузки файла, либо баг в нормализации ID.

Код проверки: `src/chat_monitor/userbot.py:1311`. Структура загрузки: `_load_banned_chats()` и `_mark_chat_banned()`. Ban detection описан в шапке файла комментарием «loud alert if Артём gets kicked/banned from a channel».

**Что проверить:**
- В рантайме набор `_banned_chat_ids` содержит `1158193643` или `-1001158193643`?
- Если да — почему этот ID не оказался в `data/banned_chats.json`? Похоже на race condition или забытый persist.
- Был ли реальный `ChatWriteForbiddenError` в этом чате на ранних запусках? Поискать в журнале раньше 24.04.

**Quick-fix:** руками очистить `_banned_chat_ids` (рестарт сервиса перечитает только файл, а в файле этот чат не значится). Но это не решит проблему №1 (вахтовый чат всё равно бесполезен).

#### 3. Notion-импорт чатов отвалился молча

В журнале висит предупреждение `scheduler.job.notion_import.no_token` каждые 5 минут (см. 05:00:00). Похоже, плановое пополнение `hr_chats.json` из Notion-базы не работает, потому что в `.env` нет `NOTION_TOKEN` (либо переменная названа иначе).

Найти job в `src/orchestrator/` и понять, какое именно поле он читает. Решение: либо отдать ему токен, либо отключить job, если этот канал пополнения вообще решено не использовать.
